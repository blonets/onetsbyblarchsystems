# دليل التركيب والربط للفنيين — منصة إدارة راوترات MikroTik

> الدليل ده مخصص للفني الميداني. مفيش أي إعدادات يدوية معقدة: سطر أوامر واحد يتم لصقه في الـ Terminal الخاص بالراوتر، والراوتر بيظهر في اللوحة الرئيسية بحالة **🟢 online** تلقائياً.

---

## 📋 قبل الذهاب للموقع

1. **استخراج التوكن (Onboarding Token)**:
   - افتح اللوحة (`admin.onetsbyblarch.online`).
   - ادخل على الموقع المطلوب (`Sites → اسم الموقع`).
   - اضغط **Onboard Router** لإنشاء توكن جديد.
   - **هام**: التوكن صالح للاستخدام **مرة واحدة فقط** وله صلاحية **15 دقيقة**. لو انتهى الوقت، أنشئ توكناً جديداً.
2. **المعدات المطلوبة**:
   - لابتوب أو موبايل مثبت عليه **WinBox** أو تطبيق SSH، مع كابل إيثرنت.
3. **جاهزية الإنترنت**:
   - تأكد أن الراوتر متصل بالإنترنت ومفعل عليه DNS والوقت (حتى لو خلف NAT أو مزود 4G، لا يلزم وجود Static IP عام في الموقع).

---

## ⚡ الخطوة 1: نسخ سطر الربط التلقائي

من شاشة الربط في اللوحة ستجد السطر الجاهز (مع استبدال `<TOKEN>` بالرمز الخاص بك):

```routeros
/tool fetch mode=https url="https://api.onetsbyblarch.online/api/v1/onboard/<TOKEN>/onboard.rsc" dst-path=onboard.rsc check-certificate=no; :delay 2s; /import onboard.rsc
```

> **ملاحظة فنية**: الأمر متوافق 100% مع أنظمة **RouterOS v6.49+** وأنظمة **RouterOS v7+**، ويحتوي على `:delay 2s` لضمان اكتمال تحميل الملف قبل تشغيله.

---

## 💻 الخطوة 2: اللصق والتنفيذ على الراوتر

1. افتح برنامج **WinBox** وسجل الدخول على الراوتر بحساب الأدمن.
2. من القائمة الجانبية افتح **New Terminal**.
3. الصق السطر كاملاً واضغط **Enter**.
4. انتظر 5 إلى 15 ثانية، وستظهر رسائل النجاح:
   ```text
         status: finished
     downloaded: 2KiB
          total: 2KiB
       duration: 1s
   Opening script file onboard.rsc
   Script file loaded and executed successfully
   ```

> ⚠️ **تحذير**: لا تغلق نافذة الـ Terminal ولا تفصل الراوتر أثناء تشغيل السكريبت.

---

## 🔍 ماذا فعل السكريبت تلقائياً على الراوتر؟

| الإعداد | التفاصيل التقنية |
|---|---|
| **اتصال SSTP الآمن** | إنشاء عميل SSTP (`sstp-hub`) يتصل بنفق VPN مشفر عبر منفذ `TCP 443` إلى السيرفر الرئيسي `vpn.onetsbyblarch.online`؛ يتخطى أي جدران نارية وحجب مزودي الخدمة دون فتح أي بورتات محلية. |
| **مستخدم إدارة مقيد `panel-api`** | إنشاء مستخدم مخصص للوحة بصلاحيات محددة لإدارة الهوت سبوت ومراقبة الأداء، مع حظر صلاحيات كشف كلمات المرور أو إعادة تشغيل الجهاز دون إذن. |
| **هوية الراوتر الفريدة (UUID)** | تثبيت معرف فريد مشفر داخل `/system note` لربط الراوتر بالموقع وسجلاته في قاعدة البيانات. |
| **جدولة الفحص الذاتي (Watchdog)** | إنشاء مهمة مجدولة في `/system scheduler` تفحص نفق الـ SSTP كل دقيقتين، وتعيد تشغيل الاتصال ذاتياً في حال حدوث أي انقطاع مؤقت للإنترنت. |
| **حرق التوكن وتأكيد الربط** | يرسل الراوتر إشعار نجاح للوحة، مما يؤدي لحرق التوكن فوراً لمنع استخدامه مرة أخرى. |

---

## ✅ الخطوة 3: التأكد من ظهور الراوتر في اللوحة

1. ارجع للمتصفح في اللوحة: `admin.onetsbyblarch.online` → **Routers**.
2. ستجد الراوتر ظهر بحالة **🟢 online** مع ظهور الـ Tunnel IP الخاص به (مثال: `10.200.0.7`).
3. اضغط على الراوتر للتأكد من قراءة البيانات الحية:
   - نسبة استهلاك المعالج **CPU %**.
   - استهلاك الذاكرة **RAM**.
   - سرعة السحب والرفع لكل كارت شبكة **Traffic (bps)**.
   - عدد عملاء الهوت سبوت المتصلين حالياً.

إذا ظهرت البيانات، فإن عملية الربط **تمت بنجاح كامل وجاهزة للتشغيل**.

## 🛠️ جدول استكشاف الأعطال وحلولها (Troubleshooting)

| العَرَض | السبب المحتمل | الحل السريع |
|---|---|---|
| `fetch failed` أو `connection timeout` | لا يوجد إنترنت على الراوتر، أو الـ DNS غير مضبوط، أو انتهت صلاحية التوكن (15 دقيقة) | 1. افحص الإنترنت عبر الـ Terminal: `/ping 8.8.8.8`<br>2. تأكد من إعدادات الـ DNS: `/ip dns print`<br>3. إذا كان كل شيء سليم، أعد إنشاء توكن جديد من اللوحة. |
| `import: script error` | تم نسخ السطر ناقصاً أو تم فصل الراوتر | انسخ السطر كاملاً مرة واحدة ونفذه مجدداً. |
| تم تنفيذ السكريبت ولكن الراوتر يظهر `offline` | نفق الـ SSTP لم يتصل بالسيرفر | 1. نفذ: `/interface sstp-client print`<br>2. تأكد من وجود حرف **R** (Running) بجانب اتصال `sstp-hub`.<br>3. إذا لم تجد حرف R، نفذ أمر إعادة التفعيل:<br>`/interface sstp-client disable [find name=sstp-hub]`<br>`/interface sstp-client enable [find name=sstp-hub]` |
| النفق متصل (R) ولكن البيانات لا تظهر في اللوحة | مشكلة في صلاحية مستخدم `panel-api` | 1. تأكد من وجود المستخدم: `/user print where name=panel-api`<br>2. تفقد سجلات الـ Watchdog:<br>`/log print where topics~"panel-watchdog"` |

## 📌 أوامر تشخيصية سريعة (Terminal Quick Commands)

```routeros
# فحص حالة نفق الإدارة
/interface sstp-client print

# فحص الآي بي الداخلي للنفق (يبدأ بـ 10.200.)
/ip address print where interface~"sstp"

# إعادة تشغيل نفق الإدارة يدوياً
/interface sstp-client disable [find name=sstp-hub]
/interface sstp-client enable [find name=sstp-hub]

# مراجعة سجلات الـ Watchdog التلقائية
/log print where topics~"panel-watchdog"

# التأكد من مستخدم اللوحة
/user print where name=panel-api
```

## ⛔ تعليمات هامة ومحظورات

- 🚫 **لا تقم بحذف** مستخدم `panel-api` أو جدول `panel-watchdog` حتى لا ينقطع اتصال اللوحة بالراوتر.
- 🚫 **لا تغير** إعدادات السيرفر أو اسم المستخدم وكلمة مرور الـ SSTP يدوياً؛ المنصة تدير وتحدث هذه البيانات عبر النفق المشفر.
- 🚫 **لا تشارك** رابط التوكن على تطبيقات المراسلة غير الآمنة.
